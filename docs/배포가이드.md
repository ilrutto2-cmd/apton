# 배포 가이드

두 가지 방법 중 하나를 고르세요.

| | A. Vercel + Supabase | B. 서버 한 대(Docker) |
|---|---|---|
| 비용 | 무료 요금제로 시작 가능 | 소형 VM 월 수천~1만원대 |
| 예약 발송 | 외부 크론이 1분마다 호출(설정 필요) | 서버가 직접 30초마다 실행 |
| 난이도 | 쉬움 | 보통(도메인·HTTPS 설정) |

## 공통: 환경변수

`.env.example`을 참고합니다.

| 이름 | 필수 | 설명 |
|---|---|---|
| `DATABASE_URL` | ✔ | PostgreSQL 주소 |
| `APP_URL` | ✔ | 서비스 주소(예: `https://apton.example.kr`) — 문자 속 링크에 사용 |
| `DATA_ENCRYPTION_KEY` | ✔ | `openssl rand -base64 32` 결과. **바꾸면 기존 번호를 못 읽으니 안전하게 보관** |
| `CRON_SECRET` | ✔ | `openssl rand -hex 24` — 예약 실행 주소 보호 |
| `ADMIN_SIGNUP_CODE` | 권장 | 첫 관리자 이후 가입에 필요한 코드(비우면 추가 가입 불가) |
| `SOLAPI_API_KEY` / `SOLAPI_API_SECRET` | 실제 발송 시 | 비우면 테스트 모드만 가능 |
| `SCHEDULER` | | `internal`(서버 직접 실행) / `off`(외부 크론) |
| `ANTHROPIC_API_KEY`, `AI_MODEL` | 선택 | AI 공지 작성 보조 |

## 실제 문자 발송 준비 (SOLAPI)

1. https://solapi.com 가입 → 충전(선불)
2. **발신번호 등록**: 관리사무소 대표번호를 등록·인증(전기통신사업법상 사전 등록된 번호만 발신 가능)
3. 콘솔 → API Key 관리 → API Key / API Secret 발급 → 서버 환경변수에 입력 후 재배포
4. 아파트온 `설정` → `연결·잔액 확인(무료)` → `내 휴대전화로 1건 보내기`(약 18원) → 발송 방식 `실제 발송` 저장
5. 결과 수신: 서버가 1분 이내 주기로 SOLAPI 결과 조회 API를 호출해 상태를 갱신합니다(웹훅 설정 불필요).

## A. Vercel + Supabase

1. **Supabase** 프로젝트 생성 → Project Settings → Database → Connection string(URI, *Transaction pooler* 6543 포트)를 `DATABASE_URL`로.
2. 코드를 GitHub 저장소에 올리고 **Vercel**에서 Import. Environment Variables에 위 값 입력, `SCHEDULER=off`.
   - `vercel.json`이 빌드 때 `npm run db:migrate`로 테이블을 만듭니다.
3. 배포 주소를 `APP_URL`에 넣고 다시 배포.
4. **예약 발송 크론(필수)** — Vercel 무료 요금제의 Cron은 하루 1회라 예약에 쓸 수 없습니다. 다음 중 하나로 1분마다 호출하세요.
   - Supabase SQL Editor (pg_cron·pg_net 확장 활성화 후):
     ```sql
     select cron.schedule('apton-dispatch', '* * * * *', $$
       select net.http_get(
         url := 'https://<내 주소>/api/cron/dispatch',
         headers := jsonb_build_object('Authorization', 'Bearer <CRON_SECRET>')
       );
     $$);
     ```
   - 또는 cron-job.org 등 외부 크론: URL `https://<내 주소>/api/cron/dispatch`, 헤더 `Authorization: Bearer <CRON_SECRET>`, 1분 간격
5. `https://<내 주소>/api/cron/dispatch`를 헤더 없이 열면 `unauthorized`가 나와야 정상입니다.

## B. 서버 한 대(Docker)

```bash
cp .env.example .env   # 값 채우기 + DB_PASSWORD 추가, APP_URL은 https 주소
docker compose up -d --build
```
- 앱이 시작될 때 테이블을 자동으로 맞추고, 30초마다 예약 발송·결과 확인을 실행합니다.
- HTTPS: Caddy 같은 리버스 프록시를 앞에 둡니다(예: Caddyfile `apton.example.kr { reverse_proxy localhost:3000 }`).
- 백업: `docker compose exec db pg_dump -U apton apton > backup.sql` 를 주기적으로.

Docker 없이 직접: `npm ci && npm run db:migrate && npm run build && SCHEDULER=internal npm start` (pm2·systemd로 상시 실행)

## 운영 전 점검

- [ ] `APP_URL`이 https이고 실제 주소인지 (문자 링크)
- [ ] `DATA_ENCRYPTION_KEY` 별도 안전 보관
- [ ] 샘플 데이터 미사용 또는 삭제, 샘플 계정 비밀번호 변경
- [ ] 테스트 모드로 공지 1건 → 결과 확인 → 실제 발송 연결 테스트 1건
- [ ] 예약 공지를 2~3분 뒤로 걸고 브라우저를 닫은 뒤 발송되는지 확인
- [ ] 관리사무소 개인정보 처리방침에 문자 발송 위탁(SOLAPI)·보관 기간 반영 (`/privacy` 예시 참고)
