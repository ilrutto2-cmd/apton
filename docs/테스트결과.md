# 기능별 테스트 결과

검증일: 2026-10-30 (KST) · 환경: Linux, Node.js 22, PostgreSQL 16, Next.js 15 프로덕션 빌드(`npm start`, 내장 예약 실행기), Chromium(Playwright)

**여기 적힌 결과는 실제로 실행해 확인한 것만입니다.** 실제 SOLAPI 계정 키가 없어 실제 문자 발송은 확인하지 못했습니다(아래 11번 참고).

## 1) 자동 테스트 — `npm test` : 40개 모두 통과

실제 PostgreSQL 테스트 DB에서 실행.

- 발송 대상: 특정 동/호수/전체 선택 시 해당 주민만, 다른 동·다른 아파트(같은 이름의 101동 포함) 제외
- 중복 방지: 여러 세대에 같은 번호 → 1건 / 같은 회차를 즉시 실행 2번 + 스케줄러 2번 **동시에** 돌려도 문자 5건만 / 같은 요청 키 회차 중복 생성 차단 / 응답 없는(네트워크 오류) 묶음은 이후 주기에도 재전송 안 함 / 발송 도중 멈춘 건은 재전송 없이 '결과 확인 불가'
- 예약: 시각 전에는 미발송, 지나면 주기 작업만으로 발송 / 취소된 예약 미발송 / 발송 시점 기준 전출자 제외
- 실패: 테스트 모드 끝자리 0000 → 3043 실패·요금 0원·공지 '일부 실패' / 문자 서비스 거부 시 사유와 함께 전체 실패 / 접수(2000)만으로 성공 표시 안 함
- 분리: 다른 아파트 동·호수 ID로 대상 지정 거부
- 테스트 모드: 외부 네트워크 호출 0회 / 실제 모드인데 키 없으면 발송하지 않고 이유 기록
- 자격: 동의 전·거부·샘플(실제 발송) 제외, 하루 발송 한도, 세대별 개인 링크 토큰이 수신자마다 다름
- SOLAPI 연동 코드(가짜 서버): HMAC-SHA256 헤더 서명 검증, `send-many/detail` 요청 본문(발신번호·LMS 제목·customFields), 접수/접수실패 응답 해석, 4xx=거부 / 5xx·네트워크=알 수 없음, 결과 조회 쿼리·상태 반영
- 기타: 문자 바이트·SMS/LMS 판정, 요구사항 예시와 동일한 문자 형식, 재안내 시각 계산, 전화번호 정규화, 암호화/복호화, 호수 생성, CP949 CSV·xlsx 읽기, AI 결과의 '메모에 없는 숫자' 감지

## 2) 브라우저 시나리오 — 32개 모두 통과

데스크톱 1280px + 모바일 390px, 관리자 화면은 실제 클릭·입력으로 진행.

| 요구 테스트 | 결과 | 확인 내용 |
|---|---|---|
| 1. 관리자 로그인 | ✅ | 잘못된 비밀번호 거부, 정상 로그인 |
| 2. 아파트·동·호수 등록 | ✅ | 104동(1~3층×2) 생성 6세대, 두 번째 아파트 가입 |
| 3. 전화번호 저장·수정 | ✅ | 암호문으로 저장 확인, 번호 변경 후 뒷자리 반영, 전체 보기 시 이력 기록, CSV 일괄 등록(없는 동·잘못된 번호 줄 보고) |
| 4. 특정 동만 발송 | ✅ | 시나리오: 엘리베이터 점검·내일 10~13시·101동 → 미리보기 14명 = DB 적격 수신자 14명 → 확인 창 → 발송 → 전원 '발송 성공 확인' |
| 5. 다른 동 오발송 없음 | ✅ | 101동 공지 수신자 전원 101동, 102동 예약 공지 수신자 전원 102동 |
| 6. 중복 문자 없음 | ✅ | 회차 내 번호 중복 0 |
| 7. 브라우저 종료와 무관한 예약 | ✅ | 예약 후 **브라우저 종료** → 00:39 예약분이 00:39:26 서버가 발송·완료 |
| 8. 실패 내역 기록 | ✅ | 102동 501호 `[3043] 단말기 전원 꺼짐(가상)` 표시, '실패 1건 재발송'으로 해당 1건만 재발송 |
| 9. 다른 관리자에게 미노출 | ✅ | 다른 아파트 관리자: 공지 상세 URL 직접 접근 404, 연락처·공지·대시보드 0건 |
| 10. API 없이 테스트 모드 | ✅ | 전 과정 테스트 모드로 수행, 예약 취소 확인 |
| 11. 실제 API 설정 시 실제 발송 | ⚠ 미확인 | 연동 코드는 SOLAPI 문서 규격 기준 + 가짜 서버로 검증. **실제 키로 문자 1건 보내는 확인은 키 등록 후 필요** (설정 → '내 휴대전화로 1건 보내기') |
| 12. 발송 내역 재확인 | ✅ | 상세 화면 수신자별 결과, 공지 내역 검색 |
| 13. 모바일·PC | ✅ | 390px에서 대시보드·공지 작성 가로 넘침 없음, 모바일에서 작성→확인→발송 완료 |
| 입주민 페이지 | ✅ | 로그인 없이 공개 공지 목록·상세(일시·대상), 취소된 공지 비공개, 비로그인 관리자 화면 차단 |

## 테스트 중 발견해 고친 문제

- 로그인 실패 후 이메일 칸이 지워짐(React 폼 자동 초기화) → 모든 입력 폼이 오류 후에도 값을 유지하도록 수정
- 동·호수 화면의 '연락처 등록 세대 수'가 항상 0 → 하위 쿼리 컬럼 참조 수정(입주민 페이지의 발송일 쿼리도 같은 문제 수정)
- 공지 작성 미리보기가 요청 키 누락으로 계산되지 않음 → 수정
- AI '지어낸 숫자' 감지가 다음 주 날짜 숫자를 모두 허용하던 약점 → 메모에 '내일' 등 표현이 있을 때만 허용

## 확인하지 못한 것

- 실제 SOLAPI 계정으로의 발송·결과 수신, 잔액 조회
- AI 공지 작성 보조의 실제 응답(키 없음 — 키가 없을 때 메뉴가 숨겨지고 나머지 기능이 정상인 것은 확인)
- Docker 이미지 빌드(이 환경에 Docker 데몬 없음), Vercel·Supabase 실제 배포
- 실제 휴대전화 기기에서의 문자 표시
